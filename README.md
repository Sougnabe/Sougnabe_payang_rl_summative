# student_name_rl_summative

Mission-based reinforcement learning benchmark comparing:
- DQN (value-based)
- REINFORCE (policy gradient)
- PPO (policy gradient)
- A2C (actor-critic)

All agents are trained on the same custom Gymnasium environment:
`DisasterResponseMission-v0`.

## 1. Mission Description

This project models a **disaster-response drone** that must:
1. Navigate a hazardous area with stochastic wind,
2. Scan to discover stranded victims,
3. Deliver medical kits,
4. Return to base before battery depletion.

The environment is designed to be non-trivial and production-relevant for capstone domains such as emergency logistics, autonomous mobility, and mission planning.

## 2. Environment Specification

### Action Space (12 discrete actions)
0. Hover
1. Move North
2. Move South
3. Move East
4. Move West
5. Move North-East
6. Move North-West
7. Move South-East
8. Move South-West
9. Descend + Scan
10. Deliver Kit
11. Emergency Return-to-Base vector command

### Observation Space (20-dimensional continuous vector)
- Agent normalized position (2)
- Relative base vector (2)
- Battery level (1)
- Kits remaining (1)
- Wind vector (2)
- For each of 3 victim sites: relative vector (2), pending flag (1), discovered flag (1)

### Reward Design
- Small per-step cost to encourage efficiency.
- Additional motion-energy penalty.
- Hazard penalties for entering danger zones.
- Positive reward for successful victim discovery.
- Large reward for successful kit delivery.
- Penalty for invalid delivery attempt.
- Terminal bonus when all victims are served and drone returns to base.
- Large terminal penalty for battery depletion.

### Start State
- Drone at base, full battery, 3 kits, no victims discovered.

### Terminal Conditions
- Success: all deliveries complete and drone returns to base.
- Failure: battery depleted.
- Truncation: max-step limit reached.

### Visualization
- Environment supports both `rgb_array` and `human` rendering through custom renderer in [environment/rendering.py](environment/rendering.py).
- Static report visual can be generated by:

```bash
uv run training/visualize_env.py
```

This saves [assets/environment_snapshot.png](assets/environment_snapshot.png) after the first run.

## 4. Setup and Execution (UV)

### Install dependencies

```bash
uv sync
```

### Train one algorithm

```bash
uv run main.py --algo dqn --timesteps 80000
uv run main.py --algo reinforce --timesteps 80000
uv run main.py --algo ppo --timesteps 80000
uv run main.py --algo a2c --timesteps 80000
```

### Train all algorithms

```bash
uv run main.py --algo all --timesteps 80000
```

### Hyperparameter sweeps (10 runs per algorithm)

```bash
uv run training/experiments.py --algo dqn --timesteps 70000
uv run training/experiments.py --algo reinforce --timesteps 70000
uv run training/experiments.py --algo ppo --timesteps 70000
uv run training/experiments.py --algo a2c --timesteps 70000
```

Or run all sweeps:

```bash
uv run training/experiments.py --algo all --timesteps 70000
```

### Generate report charts/tables

```bash
uv run training/analysis.py
```

Outputs are written to [assets/charts](assets/charts).

### Create simulation video from best model

```bash
uv run training/play.py --algo dqn --model-path models/dqn/default/model.zip --output assets/videos/dqn_demo.mp4
```

Equivalent commands exist for `reinforce`, `ppo`, and `a2c`.

## 6. Report Checklist (7 to 10 pages)

1. Problem statement and mission objective.
2. Environment design with action/state/reward/start/terminal details.
3. Hyperparameter tables with 10 runs each for DQN, REINFORCE, PPO, A2C.
4. Plots: reward distribution, best runs, and algorithm comparison.
5. Discussion: convergence, stability, exploration-exploitation, and failure modes.
6. Include at least one environment visual from [assets/environment_snapshot.png](assets/environment_snapshot.png).
7. Conclude with best model and practical deployment relevance.

## 7. Video Checklist (5 minutes)

1. Full screen share and camera on.
2. Briefly explain problem and objective.
3. Explain reward structure and expected behavior.
4. Show terminal commands and run simulation.
5. Demonstrate best-performing agent in GUI/video playback.
6. Interpret agent behavior and performance.

## 8. Notes

- REINFORCE is implemented directly in PyTorch for exact algorithm fidelity.
- PPO, A2C, and DQN are implemented with Stable-Baselines3.
- All methods use the exact same custom environment for objective comparison.
